# Audit Pytest Blackbox Tests

Read the complete [shared policy](../../core/POLICY.md), [semantic reconciliation protocol](../../references/reconciliation.md), and [review checklist](../../references/review-checklist.md) before acting. Confirm the audit boundary and inventory every reachable or registered contract-bearing operation from the final framework route/action/handler registrations, including method-specific actions synthesized by a framework. Exclude broker topology and consumer/handler registration from that operation census; verify them separately as one private production-bootstrap fixture invariant with no collected topology cases. Apply every reconciliation pass: operation ownership and bottom-up names, requirements to tests, tests back to precise authority, applicable scenario dimensions, complete positive/negative promises, and counterfactual source conditions. Application source reveals candidates only. Report undocumented source-only behavior as `ambiguous` or an existing unsupported test as `unsourced`; never bless either as the oracle. Generalized policy decisions may scope only non-contract surfaces and the recorded concurrency boundary; they never exempt public or registered contracts. A primary contract file or green suite is never sufficient evidence by itself.

If `[tool.pytest-blackbox]` is absent, run read-only discovery first and explicitly confirm temporary project-wide choices needed by this audit, especially concurrency and generalized non-contract coverage. Do not mutate configuration during the read-only audit. Report the missing configuration and temporary choices as a limitation; if the user wants persistent policy or a conformance claim beyond that temporary boundary, finish the separate onboarding workflow before continuing.

Read [tooling.md](../../references/tooling.md). For a whole-suite audit, run `../../scripts/audit_suite.py <project-root>` without scope. For an explicitly named complete component surface, pass its owning test directory and every shared-support path used by the component through repeatable `--scope`; never sample only convenient files inside the promised component. The command includes mechanically proven diagnostics plus preserved semantic review. Separately run relevant pytest collection/execution plus the project's own lint and type checks; the bundled audit command does not run project code. Auto mode uses the enhanced toolchain only after dependency opt-in; bundled fallback remains supported without a managed install. Treat deterministic output as evidence, not proof of semantic completeness. Reconcile every emitted `SEM*` item, especially `SEM006` and `SEM013`–`SEM017`, with concrete test nodes and source/contract evidence rather than suppressing or restating it. When available and authorized, use independent subagents for large functional surfaces; the primary agent retains ownership of the census, policy decisions, reconciliation, and final findings.

Keep the audit read-only. Report prioritized findings, tested evidence, excluded surfaces, warnings, manual-review items, and matrix counts for `covered`, `partial`, `missing`, `ambiguous`, and `unsourced`. Do not call the selected scope complete unless the last four counts are zero. Do not repair findings unless the user separately authorizes changes.
