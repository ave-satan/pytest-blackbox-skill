# Audit Pytest Blackbox Tests

Read the complete [shared policy](../../core/POLICY.md) and [review checklist](../../references/review-checklist.md) before acting. Confirm the audit boundary and inventory every reachable or registered contract-bearing operation from the final framework route/action/handler registrations, including method-specific actions synthesized by a framework. Exclude broker topology and consumer/handler registration from that operation census; verify them separately as one private production-bootstrap fixture invariant with no collected topology cases. Then perform two distinct semantic reconciliations: operation completeness maps every identity to its owning collected component; scenario completeness derives expected truth from authoritative requirements and uses application-owned source behavior only to discover candidate public outcomes, state partitions, compound ownership/isolation dimensions, validation boundaries, handler no-op/stale/mismatch outcomes, mixed batch partitions, and direct artifacts. Map every confirmed contract item to a collected node; report an undocumented source-only candidate as a finding/question rather than blessing current behavior as the oracle. Generalized policy decisions may scope only non-contract surfaces and the recorded concurrency boundary; they never exempt public or registered contracts. A primary contract file or green suite is never sufficient evidence by itself.

If `[tool.pytest-blackbox]` is absent, run read-only discovery first and explicitly confirm temporary project-wide choices needed by this audit, especially concurrency and generalized non-contract coverage. Do not mutate configuration during the read-only audit. Report the missing configuration and temporary choices as a limitation; if the user wants persistent policy or a conformance claim beyond that temporary boundary, finish the separate onboarding workflow before continuing.

Read [tooling.md](../../references/tooling.md). Run `../../scripts/lint_suite.py <project-root>` for mechanically proven diagnostics, then `../../scripts/audit_suite.py <project-root>` for the preserved semantic review. Separately run relevant pytest collection/execution plus the project's own lint and type checks; the bundled audit command does not run project code. Auto mode uses the enhanced toolchain only after dependency opt-in; bundled fallback remains supported without a managed install. Treat deterministic output as evidence, not proof of semantic completeness. Reconcile every emitted `SEM*` item, including `SEM006`, with concrete test nodes and source/contract evidence rather than suppressing or restating it. When available and authorized, use independent subagents for large functional surfaces; the primary agent retains ownership of the census, policy decisions, reconciliation, and final findings.

Keep the audit read-only. Report prioritized findings, tested evidence, excluded surfaces, warnings, and manual-review items. Do not repair findings unless the user separately authorizes changes.
